## Правила проекта

### Автокоммит

Каждое законченное изменение сразу коммить в текущую ветку, не спрашивая разрешения: один логический шаг — один коммит с сообщением на русском. Рабочее дерево после завершения задачи остаётся чистым. Push делается только по просьбе: push в `main` выкатывает игру на GitHub Pages.

### Процесс разработки

Спецификация — `PLAN.md`, тикеты — GitHub Issues с меткой `ready-for-agent`, у каждого указаны блокеры. Интеграционная ветка — `replay`; в `main` ничего не попадает до закрытия последнего тикета.

Тикет проходит конвейер из независимых агентов. Проверяющие получают только тикет, спецификацию и результат, без пояснений автора.

1. Исполнитель работает в своём worktree на ветке от `replay`, пишет код и тесты (сначала тест, потом код), коммитит, перед сдачей вливает в свою ветку свежий `replay` и прогоняет команду проверки (см. «Проверка в браузере»): сдаёт ветку, только когда она зелёная.
2. Тестер код не правит. Начинает с команды проверки `node tools/check.mjs`: она гоняет тесты и ботов, проходит базовый сценарий в браузере и снимает скриншоты ключевых экранов в `frames/check/`. Дальше тестер проверяет только критерии приёмки своего тикета (в браузере, по скриншотам, своими сценариями), снимает недостающие скриншоты. Отчёт — сводка команды проверки, затем список дефектов с шагами воспроизведения или «дефектов нет» с перечнем проверенного.
3. Ревьюер читает diff ветки против `replay` по двум осям: соответствие тикету и спецификации; качество кода и правила проекта. Команду проверки ревьюер не запускает — это делает тестер. Отчёт — замечания с пометкой «блокирует» или «можно позже».
4. Критик подключается на вехах (карта и постройка, слияние, реликвии с бесконечным режимом, финальный баланс): смотрит на игру глазами игрока по скриншотам и данным ботов.

Тестер и ревьюер друг от друга не зависят и запускаются параллельно, на одной и той же ветке исполнителя (один и тот же коммит). Пока они работают, исполнитель в ветку не коммитит. Их отчёты собираются вместе: дефекты тестера и блокирующие замечания ревьюера возвращаются исполнителю одним списком, круг повторяется не больше трёх раз. Ветка вливается в `replay`, когда команда проверки зелёная, тестер подтвердил все критерии приёмки и у ревьюера нет блокирующих замечаний. После слияния тикет закрывается комментарием: что проверено и чем.

**Быстрый режим — действует сейчас, до сборки всех игровых тикетов, и отменяет шаги 2–4 и круги исправлений.** Цель — как можно раньше получить играбельную сборку всех возможностей; исправления копятся и делаются одним проходом в конце.

- Исполнитель делает тикет, вливает свежий `replay`, добивается зелёной команды проверки и сдаёт ветку. Тестера, ревьюера и кругов исправлений на тикет нет: дирижёр вливает ветку по зелёной команде проверки на объединённой ветке и закрывает тикет.
- Исполнитель отвечает за то, чтобы возможность реально работала в игре: сам играет её в браузере, смотрит свои скриншоты. Всё, что заметил, но не стал делать, перечисляет в отчёте — дирижёр запишет это в тикет хвостов #19.
- Экономия прогонов: тесты по сидам — не больше 200 сидов; партии ботов — на трёх сидах с шагом 1/30; переборов тысяч сидов и повторных прогонов «для уверенности» не делать. Команду проверки запускать, когда есть что проверять, а не после каждой правки.
- Объём — критерии приёмки тикета, без заготовок под будущие тикеты и без полировки.
- Полная проверка всей игры (тестер, ревьюер, критик) и закрытие хвостов — один раз в конце.

Остановиться и спросить человека можно только в трёх случаях: противоречие в спецификации; тупик после трёх кругов; любое действие с `main` или push.

### Проверка в браузере

Базовая проверка — одна команда из корня репозитория или worktree, без ручной подготовки:

```bash
node tools/check.mjs
```

Playwright установлен вне репозитория, путь к его пакету (`<путь к node_modules/playwright>`) лежит в переменной окружения `PLAYWRIGHT`. Переменная задаётся в окружении сессии; для Claude Code — в блоке `env` личного файла `.claude/settings.local.json` (в git не попадает), тогда строка запуска остаётся голой и разрешена без запроса. Запасной вариант для ручного запуска — префикс: `PLAYWRIGHT="<путь>" node tools/check.mjs` в Git Bash или `$env:PLAYWRIGHT="<путь>"; node tools/check.mjs` в PowerShell. Без переменной команда сразу выходит с подсказкой. Вывод в UTF-8; если в PowerShell кириллица в захваченном выводе превратилась в кракозябры, выполни `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.

Команда поднимает статический сервер на свободном порту, параллельно гоняет тесты `tests/*.test.mjs`, ботов из `tests/runs.mjs` и сценарий в Playwright по `/live/index.html` в окнах 1280 и 1920, проверяет вёрстку интерфейса, собирает ошибки консоли, гасит сервер и браузер и печатает сводку на один экран. Код возврата: 0 — всё зелёное; 1 — упал или не нашёлся тест, бот дал неожиданный итог, упал шаг сценария (в том числе не нашёлся нужный элемент), есть ошибка консоли или дефект вёрстки; 2 — команду нельзя запустить (переменная `PLAYWRIGHT`, занятый порт, неверный параметр); 130 — прервана Ctrl+C. Пропуск шага бывает только явный (`ctx.skip` с причиной) и виден в сводке. В `frames/check/` после прогона лежат скриншоты `<ширина>_<экран>.png`, лог тестов `tests.log` и `report.json` со всеми деталями.

Параметры: `--port N` — фиксированный порт (по умолчанию свободный, параллельные worktree не мешают); `--out DIR` — другой подкаталог `frames/`; `--page PATH` — другая страница того же сервера, например `/site/index.html` после `tools/build_site.py`; `--timeout SEC` — общий предел, по умолчанию 600; `--serve` — только сервер для своих сценариев: печатает адрес и работает до Ctrl+C; сам он не завершается, поэтому запускай его в фоне и гаси по окончании своих сценариев. Два прогона в одном worktree одновременно делят `frames/check/` и затирают друг другу скриншоты — так не делай, а если нужно, дай второму свой `--out`.

Очередь тяжёлых прогонов. На машине одновременно идёт один прогон с браузером: параллельные браузеры подвешивают компьютер человека. `node tools/check.mjs` встаёт в очередь сама. Свой сценарий Playwright запускай только через обёртку: `node tools/slot.mjs node frames/мой_сценарий.mjs`. Долгий счёт без браузера (боты на нескольких сидах, перебор сидов) — через отдельную счётную очередь, до трёх прогонов сразу: `node tools/slot.mjs --cpu node frames/мой_счёт.mjs`. Обёртка ждёт очереди, выполняет команду с пониженным приоритетом и возвращает её код. Ожидание в несколько минут — норма; в обход очереди браузер не запускай, два сценария сразу не запускай, браузер между шагами открытым не держи.

Только тесты, без браузера: `node --test tests/*.test.mjs` — единственная форма, одна и та же в CI (Node 20), здесь и в README (форма `node --test tests/` на Node 22+ падает: каталог не раскрывается в файлы). Для своих сценариев открывай игру на сервере `node tools/check.mjs --serve`, Playwright бери из той же `PLAYWRIGHT`, скриншоты складывай в свой подкаталог `frames/` (в git не попадает). Для Python-скриптов нужны `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`.

### Игровая часть проверки

`tools/check.mjs` — каркас, от игры не зависит. Всё, что знает про игру, лежит в `tools/check/` и `tests/runs.mjs`. Правит их исполнитель того тикета, который меняет то, на что опирается проверка (интерфейс, способ постройки, ботов или баланс), в том же тикете:

- `tools/check/game.mjs` — страница и окна, открытие страницы, помощники состояния игры (новая партия, свободные клетки под постройку, постройка, ступени веток, все ветки до потолка, перк, выбор клетки), проверка вёрстки. Поменялся способ постройки — правь помощники здесь, экраны их только вызывают. Сюда попадает только общее для нескольких экранов: помощник, нужный одному экрану, живёт в файле этого экрана.
- `tools/check/screens/NN-имя.mjs` — по файлу на экран, каркас берёт их по имени. Каждый файл получает свежую страницу и экспортирует `steps` — шаги этого экрана по порядку. Новый экран — новый файл, соседние не трогаются. Панель башни снимается на худших случаях: все ветки на потолке, самый длинный перк, недоступные действия с причиной словами; у панели появилось новое действие или состояние — добавь шаг в `30-panels.mjs`, поменялось место панели — проверь его в `35-panel-place.mjs`.
- `tests/runs.mjs` — партии ботов и их ожидаемые итоги, единые для тестов и команды проверки.

Поменял смысл поля состояния (уровень, волна, тип) — поправь явные проверки в `SIM.loadable`, порчу в `tests/save.test.mjs` и в экране продолжения `tools/check/screens/15-continue.mjs`. Числовое поле, которое законно бывает отрицательным, добавь в знаковые (`SIGNED` в sim.js) или дай ему отрицательный образец; поле, меняющее род по ходу игры, — `null` в образце. Любая правка генератора карты или его параметров обнуляет старые сейвы: карта сейва сверяется с картой от его сида.

### Карта кода

По одной строке на файл в `live/`, `tests/`, `tools/` (включая подкаталоги `tools/`). Добавил, переименовал или удалил файл в этих каталогах — обнови карту в том же коммите.

`live/` — игра, статические файлы:

- `index.html` — страница: грузит скрипты по порядку, главный цикл `APP` (мост между UI и симом), дев-перезагрузка при правке исходников.
- `config.js` — весь баланс и данные уровня: башни (вид атаки, ветки, дополнительные характеристики, вид и перки с параметрами и шаблонами описаний — новый тип добавляется записью), линии и цены Гримуара, враги (с ценой угрозы, минимальной волной, способностью и видом на перекраске чужого спрайта), параметры генератора волн и свойства волн, экономика, сетка и параметры генератора карты.
- `rng.js` — вся случайность: именованные независимые потоки от сида забега (карта, бой, дальше волны и реликвии).
- `mapgen.js` — генератор карты от сида (дорога под прямыми углами, затем препятствия, арка входа, здание склепа и особые клетки), проверка карты списком нарушений, маршрут врагов.
- `wavegen.js` — генератор волн: волна по сиду и номеру (любому, не только 1–20) — чистые данные с отрядами, свойством, боссом и характеристиками врагов, в пределах числа врагов и длительности (лишний бюджет — в силу врагов); это же превью разведки и вход модели баланса.
- `sim.js` — детерминированная симуляция: шаг, команды игрока по индексу клетки, ответы интерфейсу (в том числе итоговые характеристики башни `towerStats`, линии и цены Гримуара `grimLines`/`canGrim` и превью волны для разведки), виды атаки башен, состояние в JSON, разбор введённого сида и проверка пригодности сейва, конец забега и бесконечный режим, волны с реликвией; работает и в браузере, и в Node.
- `scene.js` — всё, что рисуется: чистая функция от времени и состояния сима.
- `ui.js` — DOM-интерфейс: HUD, карточки башен, панель клетки и башни, подсказки обучения, тосты, меню, пауза, экран победы с выбором и итогов (новый забег, переигровка сида), сейв.
- `scout.js` — панель разведки: строка в верхней полосе HUD (во время волны — сколько врагов осталось), в паузе под полосой раскрывается превью следующих волн с листанием, место выбирается там, где под ней меньше дороги; уступает панели башни и клику по полю.
- `grimoire.js` — окно Гримуара: кнопка ✦ в верхней полосе HUD и клавиша G, линии общей прокачки с ценами и причинами отказа из логики, покупка командой `grim`; поверх поля, игра идёт, закрывается по Esc и клику мимо.
- `ui.css` — стили DOM-интерфейса.
- `bgmap.js` — процедурный пиксельный фон по сгенерированной карте (препятствия, арка входа, склеп), слой перемычек поверх врагов и огни для мерцания.
- `audio.js` — процедурный звук (WebAudio) по событиям сима и кликам.
- `gl.js` — тонкий слой WebGL2: текстуры, шейдеры, квады.
- `lib.js` — движковый слой над `gl.js`: шейдеры, спрайты, тени, риги, конвейер кадра.
- `assets.js` — генерируется (prep из `tools/refresh.sh`): список текстур с размерами и кропами.
- `sizes.js` — генерируется `tools/sizes.py`: экранные размеры спрайтов.
- `rigs.js` — генерируется `tools/mkrigs.py`: риги врагов.
- `tune.cjs` — заготовка ref2game для headless-прогона демо-скрипта; у сима нет `scriptInput`, сейчас не работает.
- `assets/` — PNG-текстуры (генерируются, руками не правятся).
- `fonts/` — шрифты Alegreya (woff2) и лицензия OFL.

`tests/`:

- `game.test.mjs` — тесты забега: команды и их запреты, препятствия и бонусы особых клеток, ветки прокачки, перки, итоговые характеристики башни, шаг времени, движение врагов, детерминизм, сейв, демо, партии ботов из `runs.mjs`.
- `mapgen.test.mjs` — тесты генератора карты: годность и правила (дорога, препятствия, особые клетки) на 200 сидах, метрики качества, детерминизм, проверка карты.
- `waves.test.mjs` — тесты генератора волн: детерминизм, бюджет угрозы и предел волны, негодные номера, минимальные волны, состав, свойства, боссы, превью против того, что выходит на дорогу и происходит в бою.
- `endless.test.mjs` — тесты конца забега и бесконечного режима: победа с выбором, волны после последней, рост угрозы и босса, поражение с достигнутой волной, сейв далёкой волны, волны с реликвией.
- `enemies.test.mjs` — тесты особых врагов: разведчик (первое попадание любого урона — промах, и после сейва), знаменосец (ускоряет соседей в радиусе, с его смертью ускорение пропадает), их строки в генераторе и превью.
- `grimoire.test.mjs` — тесты Гримуара: линии и цены из конфига, покупка и её отказы, бонусы в итоговых характеристиках (и у построенных позже), закрытые типы, сейв.
- `save.test.mjs` — тесты сида и сейва: разбор введённого сида, пригодность сохранённого состояния и её порча.
- `rng.test.mjs` — тесты случайности: детерминизм и независимость именованных потоков, состояние в JSON.
- `bots.mjs` — баланс-боты (`idle`, `smart`, `spamBones`) на клетках и `play()` — партия headless; общие для тестов, `tools/balance.mjs` и команды проверки.
- `runs.mjs` — партии ботов и их ожидаемые итоги (`ok(r, all)` видит итоги всех партий по имени): единый источник для `game.test.mjs` и команды проверки.

`tools/`:

- `check.mjs` — единая команда проверки, каркас: сервер, тесты, боты, браузер, сводка, код возврата; `--serve` — только сервер.
- `check/game.mjs` — игровая часть команды проверки: страница, окна, боты, открытие страницы, помощники состояния игры, проверка вёрстки.
- `check/screens/` — шаги проверки, по файлу на экран (`NN-имя.mjs`, имя говорит, что проверяет; панели башен — `30-panels.mjs`, место панели и клик по полю — `35-panel-place.mjs`).
- `balance.mjs` — сводка баланс-ботов по сидам 1..n (`node tools/balance.mjs n`).
- `slot.mjs` — общие на машину очереди тяжёлых прогонов: браузерная (один за раз) и счётная `--cpu` (до трёх), пониженный приоритет; обёртка для своих сценариев.
- `waves.mjs` — сводка генератора волн без симуляции по сидам: число врагов, длительность, разброс суммарных HP, «следующая слабее» (`node tools/waves.mjs [сидов] [волны]`).
- `diag.mjs` — разовая диагностика smart-бота на сиде: утечки и урон башен по волнам.
- `grid.mjs` — перебор множителей HP и наград врагов против ботов.
- `build_site.py` — сборка `site/` для GitHub Pages.
- `refresh.sh` — `art/gen` → `live/assets`, `live/rigs.js`, `live/sizes.js`.
- `genretry.sh` — пакетная генерация арта с повторами.
- `genseq.sh` — генерация арта строго по одной из очереди.
- `mkrigs.py` — `tools/rigs.json` → `live/rigs.js`.
- `rigs.json` — исходные суставы ригов врагов в координатах листа.
- `rigpreview.py` — превью собранного рига рядом с цельной фигурой для проверки суставов.
- `sizes.py` — пишет `live/sizes.js`.
