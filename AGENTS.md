## Правила проекта

### Автокоммит

Каждое законченное изменение сразу коммить в текущую ветку, не спрашивая разрешения: один логический шаг — один коммит с сообщением на русском. Рабочее дерево после завершения задачи остаётся чистым. Push делается только по просьбе: push в `main` выкатывает игру на GitHub Pages.

### Процесс разработки

Спецификация — `PLAN.md`, тикеты — GitHub Issues с меткой `ready-for-agent`, у каждого указаны блокеры. Интеграционная ветка — `replay`; в `main` ничего не попадает до закрытия последнего тикета.

Тикет проходит конвейер из независимых агентов. Проверяющие получают только тикет, спецификацию и результат, без пояснений автора.

1. Исполнитель работает в своём worktree на ветке от `replay`, пишет код и тесты (сначала тест, потом код), коммитит, перед сдачей вливает в свою ветку свежий `replay` и прогоняет команду проверки (см. «Проверка в браузере»): сдаёт ветку, только когда она зелёная. Если тикет меняет интерфейс игры, исполнитель в том же тикете правит игровую часть сценария `tools/check.game.mjs`.
2. Тестер код не правит. Начинает с команды проверки `node tools/check.mjs`: она сама гоняет тесты и ботов, проходит базовый сценарий в браузере и снимает скриншоты ключевых экранов в `frames/check/`. Дальше тестер проверяет только критерии приёмки своего тикета (в браузере, по скриншотам, своими сценариями), снимает недостающие скриншоты. Отчёт — сводка команды проверки, затем список дефектов с шагами воспроизведения или «дефектов нет» с перечнем проверенного.
3. Ревьюер читает diff ветки против `replay` по двум осям: соответствие тикету и спецификации; качество кода и правила проекта. Отчёт — замечания с пометкой «блокирует» или «можно позже».
4. Критик подключается на вехах (карта и постройка, слияние, реликвии с бесконечным режимом, финальный баланс): смотрит на игру глазами игрока по скриншотам и данным ботов.

Тестер и ревьюер друг от друга не зависят и запускаются параллельно, на одной и той же ветке исполнителя (один и тот же коммит). Их отчёты собираются вместе: дефекты тестера и блокирующие замечания ревьюера возвращаются исполнителю одним списком, круг повторяется не больше трёх раз. Ветка вливается в `replay`, когда тесты зелёные, тестер подтвердил все критерии приёмки и у ревьюера нет блокирующих замечаний. После слияния тикет закрывается комментарием: что проверено и чем.

Остановиться и спросить человека можно только в трёх случаях: противоречие в спецификации; тупик после трёх кругов; любое действие с `main` или push.

### Проверка в браузере

Базовая проверка — одна команда из корня репозитория или worktree, сервер вручную поднимать не нужно:

```bash
# Git Bash
PLAYWRIGHT="C:/Users/Дмитрий/.claude/skills/ref2game/scripts/node_modules/playwright" node tools/check.mjs
# PowerShell
$env:PLAYWRIGHT="C:/Users/Дмитрий/.claude/skills/ref2game/scripts/node_modules/playwright"; node tools/check.mjs
```

Команда пишет вывод в UTF-8. Если в PowerShell кириллица в захваченном выводе превратилась в кракозябры, сначала выполни `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.

Команда сама поднимает статический сервер на свободном порту (параллельные worktree не мешают друг другу), параллельно гоняет тесты `tests/*.test.mjs`, ботов и сценарий в Playwright по `/live/index.html` в окнах 1280 и 1920, проверяет вёрстку интерфейса, собирает ошибки консоли, гасит сервер и браузер и печатает сводку на один экран. Код возврата: 0 — всё зелёное; 1 — упал тест, бот дал неожиданный итог, упал шаг сценария, есть ошибка консоли или дефект вёрстки; 2 — команду нельзя запустить (не задана `PLAYWRIGHT`, занят порт из `--port`). Параметры: `--port N` (фиксированный порт), `--out DIR` (вместо `frames/check`), `--timeout SEC` (общий предел, по умолчанию 600). В `frames/check/` после прогона лежат скриншоты `<ширина>_<экран>.png`, полный лог тестов `tests.log` и `report.json` со всеми деталями. Пропущенный шаг сценария (не нашёлся элемент, нет площадок) — не провал, но строка в сводке: если пропуск вызван твоим тикетом, поправь сценарий.

Устройство: `tools/check.mjs` — каркас, от игры не зависит; всё игровое (какие экраны открыть, куда кликнуть, какой итог ботов ожидать, проверка вёрстки) — в `tools/check.game.mjs`. Тикет, который меняет интерфейс, баланс или ботов, правит только `tools/check.game.mjs`. Ожидания ботов там повторяют `tests/game.test.mjs`: меняешь одно — поправь и другое.

Только тесты, без браузера: `node --test tests/*.test.mjs` (форма `node --test tests/` на локальном Node 24 падает: каталог не раскрывается в файлы). Для своих сценариев сверх базовой проверки игра открывается на любом статическом сервере (`python -m http.server <порт>` из корня, страница `/live/index.html`; в параллельных worktree разные порты), Playwright берётся из той же `PLAYWRIGHT`. Для Python-скриптов нужны `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`. Скриншоты складывай в `frames/` (в git не попадает).

### Карта кода

По одной строке на файл в `live/`, `tests/`, `tools/`. Добавил, переименовал или удалил файл в этих каталогах — обнови карту в том же коммите.

`live/` — игра, статические файлы:

- `index.html` — страница: грузит скрипты по порядку, главный цикл `APP` (мост между UI и симом), дев-перезагрузка при правке исходников.
- `config.js` — весь баланс и данные уровня: башни, враги, волны, экономика, дорога, площадки.
- `sim.js` — детерминированная симуляция: шаг, команды игрока, состояние в JSON; работает и в браузере, и в Node.
- `scene.js` — всё, что рисуется: чистая функция от времени и состояния сима.
- `ui.js` — DOM-интерфейс: HUD, карточки башен, панель башни, тосты, меню, пауза, экран итога, сейв.
- `ui.css` — стили DOM-интерфейса.
- `bgmap.js` — процедурный пиксельный фон карты и огни для мерцания.
- `audio.js` — процедурный звук (WebAudio) по событиям сима и кликам.
- `gl.js` — тонкий слой WebGL2: текстуры, шейдеры, квады.
- `lib.js` — движковый слой над `gl.js`: шейдеры, спрайты, тени, риги, конвейер кадра.
- `assets.js` — генерируется (prep из `tools/refresh.sh`): список текстур с размерами и кропами.
- `sizes.js` — генерируется `tools/sizes.py`: экранные размеры спрайтов.
- `rigs.js` — генерируется `tools/mkrigs.py`: риги врагов.
- `tune.cjs` — заготовка ref2game для headless-прогона демо-скрипта; у сима нет `scriptInput`, сейчас не работает.
- `assets/` — PNG-текстуры (генерируются, руками не правятся).
- `fonts/` — шрифты Alegreya (woff2) и лицензия OFL.

`tests/`:

- `game.test.mjs` — тесты `node --test`: уровень, детерминизм, баланс-боты, команды, сейв.
- `bots.mjs` — баланс-боты (`idle`, `smart`, `spamBones`) и `play()` — партия headless; общие для тестов, `tools/balance.mjs` и команды проверки.

`tools/`:

- `check.mjs` — единая команда проверки, каркас: сервер, тесты, боты, браузер, сводка, код возврата.
- `check.game.mjs` — игровая часть команды проверки: экраны и клики сценария, ожидаемые итоги ботов, проверка вёрстки.
- `balance.mjs` — сводка баланс-ботов по нескольким seed.
- `diag.mjs` — разовая диагностика smart-бота: утечки и урон башен по волнам.
- `grid.mjs` — перебор множителей HP и наград врагов против ботов.
- `build_site.py` — сборка `site/` для GitHub Pages.
- `refresh.sh` — `art/gen` → `live/assets`, `live/rigs.js`, `live/sizes.js`.
- `genretry.sh` — пакетная генерация арта с повторами.
- `genseq.sh` — генерация арта строго по одной из очереди.
- `mkrigs.py` — `tools/rigs.json` → `live/rigs.js`.
- `rigs.json` — исходные суставы ригов врагов в координатах листа.
- `rigpreview.py` — превью собранного рига рядом с цельной фигурой для проверки суставов.
- `route.py` — канонический маршрут дороги: источник для пути в `config.js` и гайда фона.
- `sizes.py` — пишет `live/sizes.js`.
