## Правила проекта

### Автокоммит

Каждое законченное изменение сразу коммить в текущую ветку, не спрашивая разрешения: один логический шаг — один коммит с сообщением на русском. Рабочее дерево после завершения задачи остаётся чистым. Push делается только по просьбе: push в `main` выкатывает игру на GitHub Pages.

### Процесс разработки

Спецификация — `PLAN.md`, тикеты — GitHub Issues с меткой `ready-for-agent`, у каждого указаны блокеры. Интеграционная ветка — `replay`; в `main` ничего не попадает до закрытия последнего тикета.

Тикет проходит конвейер из независимых агентов. Проверяющие получают только тикет, спецификацию и результат, без пояснений автора.

1. Исполнитель работает в своём worktree на ветке от `replay`, пишет код и тесты (сначала тест, потом код), коммитит, перед сдачей вливает в свою ветку свежий `replay`.
2. Тестер код не правит: запускает `node --test tests/`, ботов, открывает игру в браузере и проходит каждый критерий приёмки тикета, снимает скриншоты. Отчёт — список дефектов с шагами воспроизведения или «дефектов нет» с перечнем проверенного.
3. Ревьюер читает diff ветки против `replay` по двум осям: соответствие тикету и спецификации; качество кода и правила проекта. Отчёт — замечания с пометкой «блокирует» или «можно позже».
4. Критик подключается на вехах (карта и постройка, слияние, реликвии с бесконечным режимом, финальный баланс): смотрит на игру глазами игрока по скриншотам и данным ботов.

Блокирующие замечания возвращаются исполнителю, круг повторяется не больше трёх раз. Ветка вливается в `replay`, когда тесты зелёные, тестер подтвердил все критерии приёмки и у ревьюера нет блокирующих замечаний. После слияния тикет закрывается комментарием: что проверено и чем.

Остановиться и спросить человека можно только в трёх случаях: противоречие в спецификации; тупик после трёх кругов; любое действие с `main` или push.

### Проверка в браузере

Игра — статические файлы, сборка не нужна: `python -m http.server <порт>` из корня репозитория (или worktree), страница `/live/index.html`. В параллельных worktree бери разные порты. Playwright установлен вне репозитория; скрипты проверки берут его из переменной окружения: `PLAYWRIGHT="C:/Users/Дмитрий/.claude/skills/ref2game/scripts/node_modules/playwright"`. Для Python-скриптов нужны `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`. Скриншоты складывай в `frames/` (в git не попадает).
